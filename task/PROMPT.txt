把隔离网关的维护消息接收端做成离线模拟器，运行时不得建立真实连接。多网关可转发同一控制面消息；每条消息带来源、来源世代、有界序号、业务 ID、目的区域以及逻辑产生时刻。输入由可信世代公告、批准的源至目的规则、以及乱序到达的定长事件批构成。接收端按来源和世代分别维护接收窗口，序号仅在世代内递增，不能按序号大小跨世代比较；同业务 ID 的原请求指纹一致才允许重传。规则更新时，尚未入账的缓冲消息用新规则裁定。拒绝的序号仍占位以推进窗口，结果为可审计的拒绝回执。
ingest 按可配置最大窗口接受新消息，连续到齐时依序发放允许或拒绝的持久回执。公告声明该世代起始序号。相同来源、世代、序号绑定不同请求时拒绝整批。收到带上一世代结束序号的新世代公告后，可以预收新世代，但旧世代所有截至结束号的序号完成裁定以前，不能发放新世代回执。只允许由显式 gap 证明关闭指定缺口，并记录原因；晚来的已关闭缺口返回原回执。将裁定、窗口推进和回执写在同一事务，故障注入后重启不重复发放；dump 返回每条结果及规则版本。测试覆盖双网关重发、同 ID 异内容、窗口左右边界、换代卡在缺口、撤权后的缓冲消息、回执后响应丢失与并发 ingest。

接收规则再加入跨来源因果前置及紧急策略屏障。每条消息可引用其他来源的有限序号回执；只有本源窗口到头且全部前置均已决，才可裁定。存在被拒绝的前置时当前消息永久拒绝，区分权限拒绝和依赖拒绝。前置尚未到达时保持等待，不得越过本源序号；补齐后按 (来源,世代,序号) 选择确定的下一待决消息。依赖也可指向同批新世代消息，不能用其预收状态顶替回执。合法但互等的消息环由 inspect 返回最短环，保持窗口停住；只有显式由审计方签发的 gap 指令才可解除，指令绑定来源、世代、序号和原因并能拒绝有缓冲实体的普通消息，另设针对环中实体的显式取消。策略屏障由在事务中按逻辑序号生效的规则版本表示，更新后不得读取旧规则裁定任何后来从等待态解封的消息。测试加入撤权后前置刚就绪、两源各有本地连续消息却全局死锁、解除环后连带拒绝、幂等历史 gap、同一业务 ID 重传与关闭前置竞态。给并发和故障复原场景做独立小状态机对拍。
